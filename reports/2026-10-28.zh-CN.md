## 亮点

**新代码集中在预测市场。** scout 第一个 14 天窗口抓到的 17 个仓库里，8 个面向 Polymarket、Kalshi 或 Predict.fun。这个板块已经有两个"预测市场版 ccxt"的尝试（[PMXT](https://github.com/pmxt-dev/pmxt)、[Synpath](https://github.com/Synpath-ai/synpath)）、一个模拟交易器、一个把整个 CLOB 历史塞进一个 DuckDB 文件的索引器（[polyledger](https://github.com/nahrek/polyledger)），以及 Polymarket 官方的[智能体技能](https://github.com/Polymarket/agent-skills)。二元合约加确定的结算日期，对 LLM 来说比连续价格序列容易对付得多，这解释了为什么活动集中在这里。

**实盘结果很差，而且办比赛的人自己也这么说。** nof1 的 [Alpha Arena](https://alphaarena.ai/) 给六个前沿模型每个 1 万美元在 Hyperliquid 上交易，四个在三周内亏了 42% 到 59%。同样设置搬到 Kalshi 的后续比赛，六个全亏。开源复现 [nof0](https://github.com/wquguru/nof0) 让任何人都能重跑这个实验。共同的失败原因不是预测差，而是过度交易和仓位控制，这是系统问题，不是模型问题。

**风控板块只有六个仓库，五个不到 70 星。** 列表里每一个执行类 MCP 服务器，只要被要求就会真的下单。唯一有一定用户量的护栏形态项目是 [TradeMemory Protocol](https://github.com/mnemox-ai/tradememory-protocol)，而它是审计轨迹，不是交易前的闸门。[Agent Provost](https://github.com/CharmingSteve/agent-provost)（挡在 Alpaca MCP 服务器前面的合规防火墙）和 [pretrade-risk-controls](https://github.com/zayansalman/pretrade-risk-controls)（kill switch、支出上限、最高水位止损）形态是对的，但都很小。

**六起事故里三起是提示词注入或控制面被接管，不是交易失误。** [AIXBT](https://incidentdatabase.ai/cite/1003) 因为有人通过控制面板排入提示词丢了 55.5 ETH；[Grok/Bankr](https://giskard.ai/knowledge/how-grok-got-prompt-injected-an-x-user-drained-150-000-from-an-ai-wallet) 把一条摩斯电码消息当成转账指令执行了；[Lobstar Wilde](https://www.theblock.co/post/390722/ai-agent-created-by-openai-dev-accidentally-sends-entire-memecoin-holdings-to-reply-guy) 读错一个小数位，转出了某代币 5% 的供应量。三起的共同点是智能体可以动钱包里的钱，而没有第二道检查。

**MCP 成了集成层，券商开始官方出 server。** Alpaca、Alpha Vantage 和 Massive（原 Polygon）都发布了第一方 MCP 服务器，Polymarket 发布了技能。一年前这些全是社区封装。数据侧基本解决了；执行侧仍然只有一个官方券商 server（Alpaca），盈透、MetaTrader 和 ccxt 的都是社区版。

**这个领域刷星很常见。** 第一次周扫描的八个仓库里有五个是同一副面孔：一个 commit、零 fork、无许可证、同一天各约 150 星、README 里放 Telegram 或微信联系方式。scout 现在会标记这种模式。在交易类仓库里，star 数是比 GitHub 其他地方更弱的信号。

## 机会与开放问题

以下是读列表时看出来的供给不足的方向，不是交易想法。

1. **挡在任意执行 MCP 服务器前面的交易前风控网关。** 仓位限制、日亏损熔断、名义金额上限、标的白名单、kill switch，在模型够不到的地方强制执行。零件分散在三个小仓库里，没人把它打包成"放在智能体和券商之间的那个东西"。这是整份列表里最明显的空白。

2. **持有钱包的智能体的硬性支出上限。** 三起注入事故如果有钱包层强制的单笔和单日上限，损失都会被封顶，而不靠提示词。币安的 Agentic Wallet（签名留在交易所）是一种答案；自托管场景下的开源等价物还没出现在列表里。

3. **预测市场智能体的无污染评测。** [StockBench](https://github.com/ChenYXxxx/stockbench) 用 2024 年后的数据为股票做到了这一点。预测市场在已知日期结算，所以时点回放（T 时刻的订单簿加新闻）是可做的，[prediction-market-backtesting](https://github.com/evan-kolberg/prediction-market-backtesting) 在 Nautilus 之上开了个头。谁先做出参考基准，谁就定下别人汇报结果时要对照的标准。

4. **从预测到仓位的那一层。** 实盘竞技场的结果暗示模型预测还过得去，仓位控制很糟。一个接收概率和置信度、在 Kelly 类或回撤约束规则下返回仓位、与模型无关的库，会被列表里的每个智能体复用。

5. **面向非中文读者的 A 股工具。** 中文板块有全列表最活跃的社区项目（[easy-stock](https://github.com/jundizhou/easy-stock) 1.7k 星、[TradingAgents-CN](https://github.com/hsliuping/TradingAgents-CN)、[FinanceMCP](https://github.com/guangxiangdebizi/FinanceMCP)），几乎没有英文文档。数据获取问题（Tushare、AkShare、T+1、涨跌停）和美股差异大到足以自成一个领域。

6. **一个诚实的 "mode" 约定。** 多数仓库不说明默认是否真实下单。本列表给每条打了 `live`、`paper`、`research` 或 `library` 标签；如果这个约定能传到项目的 README 里（一行徽章就够），下一份事故报告会短一些。
